# AETHERIA — Trade Server

A dependency-free WebSocket server that powers real player-to-player trading.
The game client (`src/net/tradeClient.js`) does **not** simulate players: if this
server is offline, the trade panel stays offline.

```bash
npm run server          # ws://0.0.0.0:8787
PORT=9000 npm run server
ALLOWED_ORIGINS=https://aetheria.example npm run server
```

Health check: `GET http://localhost:8787/health` returns
`{ ok, players, trades, invites, uptime }`.

Two browsers on the same machine can trade: open the game, go to **Trade**,
enter `ws://localhost:8787`, connect, invite the other player, offer items, both
press **Ready**, then **Confirm**.

## Protocol

Messages are JSON text frames. The client sends `{ "type": "...", ...payload }`;
the server answers with the same shape.

### Handshake

| Direction | Type | Payload |
| --- | --- | --- |
| client → server | `hello` | `name`, `classId`, `level`, `zoneId`, `token` |
| server → client | `welcome` | `you: { id, name, classId, level, zoneId }` |
| server → all | `presence` | `players: Player[]` |

The `token` is a stable per-device identifier (generated by the client and kept
in `localStorage`). The server derives the player id from it, so a reconnect
keeps the same identity. Replace this with real account authentication before
production.

### Trading

| Direction | Type | Payload |
| --- | --- | --- |
| client → server | `trade:request` | `targetId` |
| server → requester | `trade:requested` | `target: Player` |
| server → target | `trade:invite` | `from: Player` |
| client → server | `trade:accept` | `fromId` |
| client → server | `trade:decline` | `fromId` |
| server → both | `trade:state` | `trade: Trade` |
| client → server | `trade:offer` | `tradeId`, `items: Item[]` |
| client → server | `trade:ready` | `tradeId`, `ready: boolean` |
| client → server | `trade:confirm` | `tradeId` |
| server → both | `trade:complete` | `trade: Trade` |
| server → both | `trade:cancel` | `tradeId`, `reason` |
| server → client | `error` | `message` |

```ts
type Player = { id: string; name: string; classId: string; level: number; zoneId: string };
type Trader = { id: string; name: string; offer: Item[]; ready: boolean; confirmed: boolean };
type Trade = { id: string; a: Trader; b: Trader };
```

## Server-side rules

- Invitations expire after 60 seconds.
- A player can be in one trade at a time.
- Offers are capped at 12 items; duplicate `uid`s are dropped.
- Items with `tradeable === false`, or with `kind` `stone`/`wing`, are rejected.
  Wings are quest/shop-only and never tradeable.
- Offers reset `ready`/`confirmed` so a changed offer needs a new confirmation.
- Both players must be ready before either can confirm.
- Completion is broadcast exactly once and the trade is deleted first, so a
  duplicate `trade:confirm` cannot duplicate items.
- Disconnects cancel the player's active trade and remove pending invites.
- Idle sockets get WebSocket pings every 25 seconds.
- Frames are capped at 64 KiB and must be masked (RFC 6455).

## Production notes

- Put the server behind TLS and use `wss://`.
- Validate `token` against your account database instead of trusting it.
- Persist completed trades for auditing.
- Run the item/economy checks on the server too; the browser copy in
  `applyCompletion` only mirrors what the server already decided.
